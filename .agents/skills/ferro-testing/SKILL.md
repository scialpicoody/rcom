# FerroUI testing

Verify UI behaviour in `cargo test` with no display. Anchor first: the ferro-crates skill ("Anchor to the pin").

## Set up

1. Dev-dependencies: `ferroui-base` and `ferroui-controls` with their `testing` features; `ferroui-headless` creates windows without a screen; `ferroui-reactive-testing` / `ferroui-reactiveui-testing` provide reactive test schedulers (time, ordering). Confirm each crate's publication and API at the pin (docs.rs).
2. Pattern source: `samples/SampleTesting` in the repo content cache — the samples' harness: a headless shell rendering frames through the compositor with Skia, per-document tests generated by the sample build, compiled-vs-runtime markup comparison, binding report guards. It is sample infrastructure: read for the pattern, adapt into the app.

## Write the tests

- **XAML/controls**: construct the class, show it in a headless window, assert on the control tree and property values — the samples' `document_<name>` / `class_<name>` shape. Input can be driven programmatically (the controls crate ships mouse/keyboard test helpers).
- **Declarative components**: signals, memos, and effects are plain Rust — test logic without mounting; use the reactive-testing schedulers for time and ordering.
- **MVVM**: view models are UI-free by design — test as ordinary Rust; keep view tests to behaviour the headless shell can render and assert.
- **Layout/rendering**: the headless shell runs real measure/arrange/composition — assert on bounds and rendered frames where a bug is visual.

## Bar

A UI change is done when headless tests pass against the pinned versions actually compiled. Tests that skip the headless shell verify markup, not UI.
